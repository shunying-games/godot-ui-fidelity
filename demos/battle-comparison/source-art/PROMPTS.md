# Generation prompts and output handling

The built-in GPT Image tool was used; the tool result did not expose a pinned backend model/version. These four prompts describe the actual generation requests. Local input filenames below replace machine-specific paths. The reference and map output were1672×941, the actor atlas1254×1254 and the chrome atlas2172×724, regardless of the requested nominal dimensions. Actual crops are in ASSETS.json.

## 1. Common full-screen design — no input image

Use case: ui-mockup. Create one polished, original FULL GAMEPLAY SCREEN reference for a playable top-down fantasy tower-defense game called MOONWELL BASTION,16:9 landscape, ideally1536x864 pixels. This image is the shared visual target for two independent Godot implementations. It must look like an actual rich indie game screenshot, not a menu, settings screen, poster, device mockup or website. Art direction: hand-painted storybook2.5D miniature diorama, midnight teal marsh, mossy raised stone islands, luminous turquoise moonwell at far right, amber lanterns, dark conifer foliage, watercolor-textured stone, glowing magic, high clarity and coherent stylish carved dark wood / aged brass HUD. Camera directly overhead with a gentle isometric feeling. The central75 percent is a large readable playable battlefield: broad pale sandstone switchback path winds from left-center across center then bends up and down and reaches the glowing moonwell near right-center. Five circular stone build pads beside the route. Two occupied pads feature a tall woodland archer spire and a warm ember brazier tower; three pads are empty and legible. Three small purple beetle-like monsters are advancing on the path, small orange/teal bolts and distinct health slivers. Scenery is rich but the path remains clear. Bottom of the world has marsh plants and rocks, not a giant blank panel.

UI composition must be deliberate and implementable using live Godot Controls. Compact dark carved top bar about72 of720 logical pixels tall. Top left small crescent crest, clear cream title MOONWELL BASTION and tiny sublabel THE LANTERN MARSH. Center rounded dark plaque with WAVE03 /08 and a second small shield plaque20 /20. Top right compact gold coin icon and360, teal crystal icon and12, then a small pause button. The game world remains visible behind edge-only HUD. Bottom center a finely bordered dark wood build dock about112 pixels high with THREE distinct illustrated tower cards, with small3D-style thumbnail silhouettes, exact names and costs: RANGER /80, EMBER /120, FROST /140. Bottom left a small two-line objective label DEFEND THE MOONWELL / Keep the lanterns burning. Bottom right large warm brass action button NEXT WAVE, with small secondary label Space to deploy. One discreet tiny wave-status pill near upper world edge. All UI labels must be crisp English, no gibberish, no excessive tiny paragraphs. Native text will replace these labels during implementation. The design should have strong game-world presence and elegant meaningful HUD hierarchy. Single full-bleed screenshot only, no comparison layout, no labels saying before or after, no watermarks, no real brands, no personal information.

## 2. Clean map — design.png as edit target

Use case: precise-object-edit. The input is the EDIT TARGET and selected visual contract. Produce the clean GAME WORLD BACKGROUND ASSET of this exact screen. Preserve canvas, camera, path shape/coordinates, island/rock/foliage/water/bridge/moonwell positions, texture style and lighting. Remove all top/bottom HUD bars, plaques, labels, cards, buttons, icons, text and UI borders; continue the marsh scenery into those edge areas. Remove the archer and ember towers, replacing footprints with empty circular stone build pads. Remove beetles, health bars, projectiles/trails and the small wave plaque. Keep the luminous moonwell as static scenery. No reframing or crop. Intended maximum runtime viewport1280×720, opaque background.

The generative edit is not a layered extraction. The actual result has six usable stone pads and small scenery differences. Shared model coordinates were measured against that result and supplied equally to both conditions.

## 3. Actor atlas — design.png as visual style reference

Use case: stylized-concept. Create a production sprite atlas with genuine transparency, nominal1024×1024, four equal2×2 cells. Each object is isolated with padding; no scene, floor tile, text, labels, UI, backing or health bars. Consistent slightly elevated isometric front camera, warm upper-left light, storybook detail readable at100px. Top-left: woodland archer spire, green banner and hooded archer/bow. Top-right: ember spire, orange banner and brazier/flames. Bottom-left: frost spire, turquoise crystals and blue banner. Bottom-right: one purple beetle, dark jointed legs and iridescent shell. Tower bases near bottom-center of each cell; tower display up to110×140px, beetle50×40px. Preserve clean source silhouettes and true alpha.

The output did not honor exact grid boundaries. Actual separator/crop coordinates were measured before deriving runtime sprites; no silhouette was cut at a nominal grid edge.

## 4. HUD chrome — design.png as visual style reference

Use case: stylized-concept. Create a transparent landscape atlas, nominal1536×512, three cells. No text or numbers. First: rectangular dark carved walnut panel with thin aged-brass frame and clipped/beveled corners, quiet woodgrain center, straight stretchable edges and small corners suitable for Godot nine-slice. Second: rectangular warm amber brass action plate with beveled clipped corners and subdued empty center for a live cream label. Third: circular dark stone/brass crest with a pale-blue crescent on a dark inset disk. All isolated with margins, matching the reference's hand-painted material. Both experimental conditions receive the same atlas.

## Public source handling

Source PNGs were re-encoded without ancillary chunks; exact decoded pixels were verified unchanged. Generated-original and released-source SHA-256 values are both recorded. The raw generated files contained a caBX provenance chunk; those original byte files remain outside Git. Runtime image derivation is reproduced by `scripts/prepare_battle_assets.py`. Runtime PNGs preserve alpha; the opaque map uses WebP. Font download and license are recorded separately.
